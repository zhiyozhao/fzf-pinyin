# 匹配设计

面向修改匹配器和缓存的开发者。输入规则以[拼音指南](pinyin.md)和[搜索语法](syntax.md)为准。

## 匹配范围与原文位置

按实际参与搜索的文本判断是否含 Unicode Han 字符；使用字段选项时，是变换后的搜索范围。无 Han 的候选直接调用原版匹配器，保留全部参数、分数、范围和位置语义。

含 Han 的候选保留原版字面结果，同时尝试拼音路径，取分数较高者；同分使用原版结果。不含拼音字母的查询沿用字面匹配。匹配范围和高亮位置始终是原文 rune 索引，不是 UTF-8 字节或展开的拼音字母。

`src/pattern.go` 负责语法、字段与匹配器选择；`src/pinyin/` 负责拼音匹配；`src/result.go` 继续负责排序。原版 `src/algo/algo.go` 不改，`src/algo/phonetic.go` 提供边界分数和归一化接口。

## 拼写与读音

一个汉字对应原字、输入法全拼、首字母或 `zh/ch/sh` 声母简拼。每条拼写只消耗一个原文字，不能跨越两个读音拼出任意字符串；查询最后匹配的字允许非空拼音前缀。普通 fuzzy 可以跳过整个原文字，其他模式在原文上约束连续性和边界。

读音来自固定版本的 `go-pinyin v0.21.0`（Normal + 多音字），不做短语消歧；可键入的拼写按输入法习惯生成，不能直接把字典注音当作键盘编码。实现为原字典加一张小的音节别名表及按字补码表：

| 范围 | 最终完整编码 |
|---|---|
| lü / nü | `lv/nv`（查询也接受 ü），不新增 `lu/nu` |
| lüe / nüe | `lve/lue`、`nve/nue` |
| j/q/x/y 后的 ü 系列 | 保留 `u/ue/uan/un`，另加对应 `v/ve/van/vn`；显式限制为 16 个合法音节，不替换其他 u |
| 嗯、哼 | 嗯 `en/ng`；哼 `heng`；不加 `eng→嗯`，删除 `hng` |
| 呣、噷 | 呣 `m/mou/mu`；噷保留 `hm/hen/xin` |
| 欸、诶、誒 | 欸保留 `ai/ei/xie` 并补 `e`；诶 `ei`；誒 `ei/xi/yi`；不统一加 `eh` |
| 呒、嘸 | 呒保留 `m/wu` 并补 `fu/mu`；嘸保留 `fu/wu/m` 并补 `mu` |
| 罕见音节 | 保留 `biang/cei/chua/den/din/eng/fiao/kei/nia/nun/rua/tei/wong/zhei` 等 ASCII 字典码；删除未经输入法依据确认的 `bong/len`，不猜测替代码 |
| 其他独立鼻音 | 保留字典已有 `n/ng/m`，不全局扩展为 `en/eng/mu` |

按字新增仅涉及嗯、呣、欸、呒、嘸五个字。非 ASCII 残留注音不会自动去重音或映射到别的音节；该字其余 ASCII 读音仍可用。首字母及 `zh/ch/sh` 从最终完整编码生成，所以嗯新增 `en` 后可用 `e` 简拼，也保留 `n`；这与输入法对完整编码取首字母的简拼规则一致。诶的 `e` 同样是 `ei` 的简拼，不代表补了一个完整读音。

保留 y/w 的正常拼写（`yin/wan/yu/yi/wu/yao` 等）及其首字母，删除旧 `zeroFinal()` 的额外 `in/uan/v/i/u/iao` 路径。不展开 `un/ui/iu` 为 `uen/uei/iou`，不做方言模糊音、错序纠错或跨字儿化；儿可用 `er`，轻声不另建码。末字前缀规则仍适用于所有合法编码，测试完整码时应接下一字，避免把末字补全误当成新增编码。

按字缓存最终拼写，不缓存用户的原行或查询。不要在并发匹配时修改读音字典、规则表或评分 scheme。

## 评分

### 排序预期

以下按同一个查询比较 A、B；其他条件相同时成立。分数优先于同分规则，不能把局部偏好当成无条件保证。

| 用户预期：A 应该排在 B 前面 | 条件与行为 |
|---|---|
| 边界上的连续全拼中文 A 应该排在同边界、内部有普通字母 gap 的零散字面 B 前面 | 同字母、同边界及连续块奖励下，整条拼音路径只扣 1，小于至少 3 的 gap 损失；新增不同边界时仍须比较奖励 |
| 连续首字母中文 A 应该排在同边界、内部有普通字母 gap 的零散字面 B 前面 | 与全拼使用相同量纲和整行扣分；default 的 `-北京`/`bj` 为 55，高于 `-b-j` 的 53 |
| 同一查询能完整拼出的词 A 应该排在把这些字母解释成很多字的缩写 B 前面 | 不再有拼写种类优先级；同字母同边界下可同分，default/path 由原文长度排序，history 保留输入次序 |
| 词首连续命中 A 应该排在词中同样命中 B 前面 | 原文边界奖励；汉字无显式词界，Han 内至少 8，分隔符后按 scheme |
| 文件名命中 A 应该排在中间目录命中 B 前面 | `--scheme=path` 的同分 pathname 规则满足；default 不承诺，不能覆盖更高分 |
| 短行 A 应该排在同样命中的长行 B 前面 | default/path 同分比原文长度；history 同分保持输入次序，不额外偏爱短行 |
| 中英混排连续 A 应该排在相同输入被打断的 B 前面 | 同一连续块跨越汉字、全拼和实际 Latin，不因脚本变化丢掉已有块奖励 |
| 汉字与拼音混打的连续 A 应该排在相同查询的间隔 B 前面 | 原字消耗一个输入字符、无转换成本；不拿不同查询的绝对分数当作一次排序 |
| 符合上下文常见读音 A 应该排在少见读音 B 前面 | 当前不承诺；单字字典无词频或语境，同成本读音同分，见取舍 |
| 当前查询恰好打全末字的 A 应该排在仅匹配末字前缀的 B 前面 | 不再承诺；`beiji` 的“北极”与“北京”同字母同边界，同分后按既有规则排序 |
| 同一词输入更多正确字母所得 A 应该强于更短输入所得 B | 这是输入过程的证据单调性，不是跨查询排序；只加实际键入字母，未输入部分不计分 |
| 同一行分数更高的对齐 A 应该排在更低分对齐 B 前面并被选中 | DP 保留块奖励状态，独立穷举核对；同分按 forward 选择较早/较晚的原文起止 |

### 与字面字符统一量纲

把一条拼写实际消耗的 k 个输入字母视作连续字符，位置仍只占一个原文 rune。记 B(i) 为当前 scheme 的原文边界奖励，F 为当前连续块的起始奖励：gap 后 F=B(i)；连续时，遇到 B(i)≥8 且 B(i)>F 则令 F=B(i)。否则保留 F，与 fzf 的连续块规则相同。

| 项目 | 分数 |
|---|---|
| 实际输入 | 16 × k |
| 同一拼写内后续输入 | max(4, F) × (k − 1) |
| 第一个匹配字 | 2 × B(i) |
| 与上一个匹配字相邻时的首字母 | max(4, F, B(i)) |
| 与上一个匹配字不相邻 | B(i) |
| 内部间隔 g 个原文字 | −3 − (g − 1) |

所有拼写的每字成本均为 0，包括全拼、输入法别名、声母、首字母和末字未完成前缀。一条匹配路径只要至少使用一次汉字的拼音边，就在总分上减 1；纯原文字面路径不扣。这个单点差只给同等证据的字面匹配保留排序优势，不随字数或打法累计；扣分后合法路径分数仍至少为 1。

B(i) 使用当前 fzf scheme 的原文边界分数。连续汉字间以及 Han 和其他字母、数字的切换处至少为 8；更高的行首、空白或分隔符奖励保留。行首必须使用 fuzzy 的初始字符类别：default 为 10，path 为 9，history 为 8。上游 `bonusAt` 的行首空白捷径不适用于 path 的 fuzzy 评分；适配层显式修正，原版代码不改。这个评分边界不改变双端引号的匹配资格，也不代表中文分词。

在同样的边界、连续块和字母数下，字面命中恰好比拼音命中高 1。例如 default 下 `/machao` 是 159；`/马超` 为 158：马的 `ma` 得 32+18+9=59，超的 `chao` 得 64+9+27=100，整条路径再扣 1。两条“马超”文件路径同分，按既有同分规则排序。

三种 scheme 的回归分数如下（同列使用同一个查询）：

| scheme | `-bj` / `bj` | `-北京` / `bj` | `-b-j` / `bj` | `-音乐` / `yy` | `-y-y` / `yy` | `/machao` / `machao` | `/马超` / `machao` |
|---|---:|---:|---:|---:|---:|---:|---:|
| default | 56 | 55 | 53 | 55 | 53 | 159 | 158 |
| path | 56 | 55 | 53 | 55 | 53 | 159 | 158 |
| history | 56 | 55 | 53 | 55 | 53 | 152 | 151 |

“长音节膨胀”应限制的是没有键入的字母，而不是实际键入的证据。只打 `z` 不会因为“中”有五个拼音字母而拿五份分；完整输入 `zhong` 则应获得五份连续证据。更长的音节在同一查询中没有免费优势，不再用固定 +4 人为压低全拼。

### 已知取舍

- 边界与 gap 仍按 fzf 权衡：default 中 `文北京`/`beijing` 为 175，`北文田田文文京` 为 176；行首优势可覆盖 `bei` 内多个字母。若要求“中文连续永远胜过零散”，就需额外的连续优先级，会偏离等价英文字母的评分，本实现不增加这个规则。
- 更强的新边界仍可能使零散匹配胜出；这与等价英文字母在上游中的行为一致。若未扣分的等价连续字面与零散字面恰好同分，整条拼音路径的 1 分扣分也可使其落后；不再存在逐字缩写成本累计导致的反转。
- 不给文件名额外的中文专属奖励。路径列表推荐 `--scheme=path`，它是 score 后的 basename 优先，default 仍按 score、length；history 不按长度排序。这些行为也在上游英文中存在。
- 多音字全部等权；不会猜测姓名、词义或上下文。“重名”和“虫鸣”对 `chongming` 同分，输入顺序决定同分次序。需要常见读音优先时，应另行选择有许可和频率信息的词组数据，不伪造现有字典的首项为词频。
- 不区分全拼、缩写与末字前缀的成本，也不按分段数扣分：`xian` 的“先”与“西安”在相同边界和连续块下同分。混打原字会改变实际输入的字符数；不同合法分段及多音字仍可能形成别的有效对齐。位置、长度和同分排序一直使用原文，不使用展开拼音长度。

### 系统检查与修复范围

修复四类实现问题：全拼内部固定 +4 导致不同量纲；跨原文字未继承连续块奖励（混排也受影响）；拼音 DP 把普通 Latin 连续的最低奖励也设成 8，使一行中无关的汉字都可能给字面匹配抬分，改回 fzf 的 4；path 行首误用空白奖励。携带块奖励后，DP 必须同时保留不同 F 的最优状态，否则较低当前分、较高 F 的路径可能被过早删除。测试也必须在独立进程初始化 scheme；上游 `Init` 是一次性接口，反复切换会遗留 path 的全局设置。

整行扣分在 `Wrap()` 中实现为 `max(原版结果, 全路径 DP−1, 纯字面 DP)`，同分仍优先原版。因为字面 DP 的 Han/Han 和 Han/Latin 边界可能高于原版，不能只做 `max(原版, DP−1)`：例如 `田abc`/`abc` 或 `国中a`/`中a` 没有用拼音，也不能扣分。仅在原版已经召回字面路径、且全路径 DP 的未扣分分数高于原版时，才顺序补算纯字面 DP；否则它不可能胜出。两次沿用相同的五个奖励槽，不增加“是否用过拼音”的状态维度。无字面命中的全拼查询只运行一次 DP。不含拼音字母的汉字查询仍完全沿用原版。

`integration/ranking_test.go` 用固定随机种子生成 30,000 行 fd 风格路径、文档/聊天标题，包含全拼、缩写、零散英文和 Go SDK 混排。六组常用查询分别用全拼和缩写，在三种 scheme 下检查整个结果序列（36 次搜索），而非只看首项；这些受控同边界、普通字母 gap 的竞争中没有违反预期。独立随机性质另覆盖 6,000 组分数/字面量纲比较；额外回归钉住上表的规则和取舍，不能把受控样本结果推广成任意文本的保证。

另用 18,000 组随机对抗比较扫描行首、空白、斜线和普通标点，以及普通字母、分隔符和空白 gap。中文落后时，用完全相同字母、边界的上游结果分成“上游也偏爱这个新边界”和“上游连续与零散同分，仅整行 1 分扣分导致反转”两类；出现两者都不能解释的反例即失败。文件名、短行和 history 的取舍也用真实上游 CLI 的英文字母对照，避免把原有排序误判为中文缺陷。

无 Han 候选继续逐参数调用上游，库分数、位置及 CLI 排序对拍不变。维护者应区分中文缺陷、上游同样的边界/同分行为和词频等产品选择，不通过改变纯英文结果掩盖取舍。

## 动态规划与复杂度

动态规划按原文 rune 和查询 rune 推进，保留全部有效分段，不贪心选择最长音节。相邻状态按连续块奖励 F 分槽，已经跳字的状态可以合并，因为下一字将重置 F；比较候选时计入各自连续奖励。各原版 scheme 的原始块奖励为 0、7、8、9、10，只分配这五个可能的槽，不为空奖励值分配状态。

设原文长度为 n，查询长度为 m，单字拼写数上界为 a，最长拼写为 l。奖励槽数 c=5 时，最坏时间 O(n × m × a × (l+c))；不回溯位置时空间 O(c×m)。只访问已到达的查询前缀列，边匹配成功后才遍历来源奖励槽；不删除任何有效分段或奖励槽。

需要位置且 n×m>65,536 时，先不留回溯节点求最优起止，再以相同原文边界和锚点在胜出区间重放。每个 live 状态的链长不超过 m，批量回收不可达回溯节点，把回溯空间限制为 O(c×m² + m×a×c + 65,536)，与 n 无关；时间仍为同一量级。此保护不截断输入、不降级算法、不改变同分路径或负分钳制规则。无 Han 路径没有新增状态开销；超长行、长查询和多音字密集输入应单独测量。`--algo=v1` 只改变字面分支，拼音分支仍使用同一动态规划。

## 缓存约束

普通 fuzzy、exact 和 prefix 匹配允许复用查询前缀的候选集。suffix、equal 和双端边界模式附带终点约束，不能假设有同样的前缀性质。

拼音匹配没有任意后缀闭包：从一个合法全拼中去掉首字母，剩余部分可能不再是合法输入。因此 `src/cache_pinyin.go` 只复用前缀候选 bitmap，不复用任意后缀结果。完整查询缓存仍然可用。

DP 状态数组通过 `sync.Pool` 独占复用，归还时清零；只保留最多 256 个查询 rune 所需的容量。池不存原行、查询、拼写或位置链，大查询用完即丢弃数组，回溯节点不入池。池可以被 GC 清空；这是 scratch 内存复用，不是结果缓存。无 Han 候选不会访问此池。

全路径 DP 和纯字面 DP 共用上述优化。`allowPinyin` 在定位和位置重放中保持相同；两次顺序调用各自归还并清空 scratch，不共享结果或 trace。Wrap 的补算条件、整行扣分和同分选择保持不变。

测试覆盖无 Han 行为一致性、独立穷举最高分、合法前缀召回、间隔性质、位置回溯、缓存和并发。运行入口见[开发指南](../CONTRIBUTING.md)。

# 验证与性能测量

面向修改匹配行为或评估性能的开发者。测试入口和环境要求见[开发指南](../CONTRIBUTING.md)。

## 什么需要验证

- 无 Han 候选的分数、范围、位置数组，以及完整 CLI 输出和排序与固定参考版本一致。
- 合法拼写的非空前缀持续召回；音节中间截断等不合法写法不能意外命中。
- 小输入用独立穷举路径核对最高分，避免只用实现本身生成预期。
- 相同拼写证据下，增加间隔不会提高分数；边界优势和不同拼写分段需要分别考虑。
- 原文位置、高亮、字段、否定、大小写及末字前缀共同工作。
- 缓存和逐字输入结果与全量重算一致；并发调用没有数据竞争。

`make check` 是提交前入口，包含以上相关 Go / CLI / PTY 检查及 race。测试数量不是行为保证，新增规则应有独立的正例和反例。

## 性能测量

### README 所引用的结果

2026-11-23，在 macOS arm64、Apple M1 Pro（8 逻辑核）、Go 1.27.4 上运行 `make bench`，参考程序来自固定上游 `bf4869b`。以下为 100,000 行无 Han 输入的完整 CLI 中位耗时，五次交替测量，包含启动和输出：

| 查询 | fzf（毫秒） | fzfp（毫秒） | 耗时比 | 两者命中行数 |
|---|---:|---:|---:|---:|
| `pr` | 60.14 | 62.15 | 1.03× | 48,895 |
| `zg` | 12.55 | 14.23 | 1.13× | 0 |
| `zhongguo` | 14.12 | 14.45 | 1.02× | 0 |
| `zhonggu` | 12.75 | 14.54 | 1.14× | 0 |
| `zzzz` | 12.45 | 13.90 | 1.12× | 0 |

这组数据说明速度接近，但不能据此保证速度完全相同；空结果查询仍有启动和分派开销，其他机器和输入需另测。纯英文结果一致性的依据是 `TestNonHanCLIParity`：20 个查询 × 13 组选项，对比完整输出顺序、stderr 和退出码，共 260 组。其适用条件是参与搜索的候选不含 Han 字符，不是只要求查询由英文字母组成。

### 复现与解释

`make bench` 使用固定生成语料：100,000 行路径形输入，分别包含无 Han 和中英混合数据。完整 CLI 测量包含启动、字典初始化、读取、匹配、排序及输出；每组预热后交替运行多次，报告中位耗时。库基准另测热调用，不包含进程启动。

比较改动前后时保持机器、Go 版本、输入、命中行数和位置回溯设置一致。不能把不同命中集合的耗时比直接当成算法开销，也不能用单行库耗时推算整个 CLI 延迟。超长行、长查询、多音字密集内容应按实际规模补测。

`make fuzz` 运行前缀召回 fuzzing；失败输入需要保留为可复现回归。完整上游终端套件另见[终端测试](e2e.md)。

测试日志和临时性能报告留在 `Artifacts/`。公开测量需注明环境、输入、方法和范围，不以累计测试数量代替行为保证。
